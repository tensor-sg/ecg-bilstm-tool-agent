# Model Card: ECG Beat Classifier (Conv-BiLSTM)

| | |
|---|---|
| Artefacts | `models/ecg_lstm.keras`, `models/ecg_lstm_meta.json`, `models/training_log.csv` (not in git; produced by notebook 02) |
| Task | Classify each heartbeat of a single-lead ECG as **N** (normal), **S** (supraventricular ectopic) or **V** (ventricular ectopic) |
| Training data | MIT-BIH Arrhythmia Database, MLII lead, 17 patients |
| Evaluation data | 22 different patients (DS2), never used for training or model selection |
| Intended use | Research and education; the `analyze_ecg` tool that the OpenAI agent calls to summarise ECG strips (also callable directly via `POST /tools/analyze_ecg/invoke`) |
| **Not intended for** | Clinical diagnosis, monitoring or any decision about a real patient |

## 1. Model

```
beat waveform (256 samples @ 360 Hz, z-scored)        RR features (4, patient-relative)
        │                                                     │
 GaussianNoise(0.1)  [training only]                  GaussianNoise(0.03)
 Conv1D 32×7 → BN → MaxPool/2                         BatchNorm → Dense 16
 Conv1D 64×5 → BN → MaxPool/2   (256 → 64 steps)              │
 BiLSTM 32 (sequences) → Dropout 0.3                          │
 BiLSTM 16                                                    │
        └──────────────────── concat ─────────────────────────┘
                     Dense 64 → Dropout 0.4 → Dense 3 (softmax)
```

About 50k parameters (49,571). Adam (lr 1e-3, halved on plateau), batch size 512, balanced class weights, at most 20 epochs,
early stopping on validation macro-F1 (patience 4). Training takes about 9 minutes on a 2-core laptop CPU
(Intel i5-7200U, about 60 s per epoch).

### Input pipeline

The same code (`app/ecg/preprocessing.py`) runs in training and in the API:

1. Resample to 360 Hz (input at any sampling rate is accepted).
2. Band-pass filter at 0.5–40 Hz (3rd-order Butterworth, zero-phase) to remove baseline wander and noise.
3. Find R-peaks: MIT-BIH annotations in training; in the API, a Pan-Tompkins-style detector, or peaks supplied by the caller.
4. Cut a window of 90 samples before and 166 after each R-peak, then z-score it per beat.
5. Compute RR features **relative to the patient's own rhythm**:
   - `pre_rr_local`, `post_rr_local`: previous and next RR interval divided by the local mean (about 10 beats)
   - `pre_rr_global`: previous RR divided by the recording's median RR
   - `pre_post_ratio`: previous RR divided by next RR (an early beat followed by a compensatory pause)

Absolute RR intervals in seconds are deliberately **not** used. They identify individual patients, and an earlier
version that used them overfit to the training subjects (see section 5).

## 2. Data and validation protocol

MIT-BIH beat labels are grouped into AAMI EC57 classes. Records are split **by patient**, following the standard
inter-patient protocol of de Chazal et al. (2004). The four paced records (102, 104, 107, 217) are excluded.

| Set | Records | N | S | V | Purpose |
|---|---|---:|---:|---:|---|
| Train | 101, 108, 109, 112, 114, 115, 116, 119, 122, 203, 207, 208, 209, 215, 220, 223, 230 | 36,436 | 686 | 2,936 | fit weights |
| Validation | 106, 118, 124, 201, 205 | 9,412 | 258 | 852 | early stopping, checkpoint and LR schedule (macro-F1) |
| Test (DS2) | 100, 103, 105, 111, 113, 117, 121, 123, 200, 202, 210, 212, 213, 214, 219, 221, 222, 228, 231, 232, 233, 234 | 44,240 | 1,837 | 3,220 | final evaluation, used once |

Why it's set up this way:
- **No patient appears in two sets.** Random beat-level splits, common in tutorials, put beats from the same
  person in both training and test sets. They report about 98–99% accuracy but don't reflect performance on new patients.
- **Selection uses macro-F1, not accuracy or loss.** Normal beats make up about 90% of the data, so "always N" already
  scores about 90% accuracy (see the baselines below).
- **Fusion (F) and paced/unknown (Q) beats are not modelled.** 373 of the 415 F beats in the training pool come from
  one patient (record 208), so F can't be learned in a way that carries over to new people. Q has 8 beats. AAMI EC57
  also doesn't count F beats against ventricular-beat detection. How the model labels these beats is still reported.
- **Confidence intervals** come from a patient-level bootstrap (1,000 resamples of test records). Beats from one
  person are highly correlated, so beat-level intervals would look far narrower than they really are.

## 3. Results on held-out patients (DS2)

Full report: [reports/evaluation.md](../reports/evaluation.md) (generated by `scripts/evaluate_model.py`).

### Overall, at annotated R-peaks

| Model | Accuracy | Macro-F1 | Balanced accuracy |
|---|---:|---:|---:|
| Majority class (always N) | 0.897 | 0.315 | 0.333 |
| RR-only logistic regression | 0.872 | 0.530 | 0.607 |
| **Conv-BiLSTM** | **0.945** [0.881–0.981] | **0.650** [0.544–0.777] | **0.630** [0.560–0.779] |

### Per class

| Class | Beats | Sensitivity [95% CI] | PPV [95% CI] | F1 |
|---|---:|---:|---:|---:|
| N | 44,240 | 0.991 [0.984–0.997] | 0.958 [0.904–0.990] | 0.974 |
| S | 1,837 | 0.096 [0.006–0.498] | 0.361 [0.069–0.514] | 0.151 |
| V | 3,220 | 0.802 [0.604–0.926] | 0.847 [0.543–0.970] | 0.824 |

### End to end, as the API runs it

Using the built-in R-peak detector instead of the annotations:

- **Beat detection:** sensitivity 0.979, PPV 0.998 (±150 ms matching window)
- **Classification of detected beats:** accuracy 0.942, macro-F1 0.642. V sensitivity 0.805 with PPV 0.814.

Performance barely changes when the model runs on its own detected beats.

### Beat types the model was not trained on

| True label | Beats | → N | → S | → V |
|---|---:|---:|---:|---:|
| F (fusion) | 388 | 380 | 1 | 7 |
| Q (unclassifiable) | 7 | 5 | 0 | 2 |

### Probability quality and speed

Full report: [reports/performance.md](../reports/performance.md) (generated by `scripts/benchmark_model.py`).

- ROC AUC (one-vs-rest): N 0.926, S 0.764, V 0.984. Brier score 0.092. Expected calibration error 0.013.
- On the 91.5% of beats with confidence ≥ 0.9, accuracy is 96.7%.
- About 0.45 ms per beat in batches; a 30-minute record is analysed end to end in about 1.3 s on a 2-core laptop CPU.
- Without record 232: accuracy 0.972, macro-F1 0.740, S sensitivity 0.382.

## 4. Limitations

- **Supraventricular (S) beats are mostly missed (sensitivity about 10%).** Of the 1,837 S beats in the test set,
  1,382 come from a single patient (record 232, sinus bradycardia with long pauses), and the model detects 2 of them.
  In that rhythm atrial premature beats are not early relative to the patient's own rhythm, which is the main cue the
  model relies on. On the other 21 test patients, S sensitivity is about 38% (174 of 455). The model should not be
  used to rule out atrial ectopy.
- **V detection varies by patient.** The 95% CI for V sensitivity is 0.60–0.93. On record 213, for example,
  103 of 220 V beats are found.
- **Fusion and paced beats are not recognised.** Fusion beats are almost always reported as N. Recordings from
  people with pacemakers are out of scope.
- **Single lead, a single database.** The model was trained on the MLII lead of MIT-BIH: 48 recordings from 47 people,
  taken from Holter tapes recorded in 1975–1979. Other leads, wearable devices, different noise conditions and other populations are untested.
- **Short strips.** RR features use the recording's own rhythm as a reference. Strips shorter than about
  10 beats give less reliable RR features, and the first and last beat of a strip may be skipped.
- **Confidence is softmax probability.** It is well calibrated on DS2 (ECE 0.013, see section 3), but this was measured on
  MIT-BIH only and may not hold on other devices.
- **Signal quality.** The R-peak detector finds "beats" even in pure noise. The API therefore reports a kurtosis-based
  `signal_quality` block; it flags noise, flat and periodic artefacts, and none of the 22 test records.

### Use as an LLM tool

The agent (OpenAI `gpt-4o-mini`, Gemini fallback) receives the full `analyze_ecg` output as JSON: heart rate,
SDNN, beat counts and percentages, up to 50 abnormal beats with confidence, `signal_quality` and the disclaimer.
It never sees the raw signal. Its system prompt tells it to quote the tool's numbers instead of guessing, mention
confidence and the limitations above (S beats, fusion and paced beats), ignore results with `signal_quality.ok =
false`, and state that the output is not a diagnosis. Live tests (`tests/test_llm_live.py`) check that the answers
quote the model's numbers and that noise is reported as noise.

## 5. Development history

| Version | Change | DS2 macro-F1 | Outcome |
|---|---|---:|---|
| v1 | 4 classes, random beat-level validation split, absolute plus relative RR features | not evaluated | discarded: validation leaked patients from the training set |
| v2 | Patient-wise validation, macro-F1 selection, 4 classes (N/S/V/F) | 0.458 | rejected: labelled about 11% of normal beats as F (memorised patient 208), S sensitivity 0.07, worse balanced accuracy than the RR-only baseline |
| **v3** | N/S/V only, patient-relative RR features, balanced weights, noise augmentation | **0.650** | shipped |

The validation set alone guided the decisions between v2 and v3. The v2 test result is reported for transparency.

## 6. Tests guarding this model

`tests/test_model.py` runs against the shipped model on DS2 patients. It checks:
- no patient leakage between the train, validation and test record lists
- the API inference path reproduces the training-pipeline predictions
- invariance to gain and DC offset
- robustness to 250 Hz input and 25 dB noise
- regression floors on accuracy, macro-F1, N/V sensitivity and V PPV
- that the model beats both baselines
- end-to-end detection quality
- signal quality passes on every DS2 record

`tests/test_model_performance.py` adds speed, memory, calibration, ROC AUC, false-alarm rate, per-patient V sensitivity
and a paired patient-level bootstrap against the RR-only baseline. `tests/test_api_integration.py` runs the same model
through the real FastAPI app, and `tests/test_llm_live.py` through the real OpenAI and Gemini agents.

## 7. Reproducing

```bash
jupyter nbconvert --to notebook --execute notebooks/01_ecg_analysis.ipynb    # downloads data, EDA
jupyter nbconvert --to notebook --execute notebooks/02_lstm_training.ipynb   # trains and writes models/
python scripts/evaluate_model.py                                              # reports/evaluation.md
pytest -m model
```

Seeds are fixed (`keras.utils.set_random_seed(42)`), but CPU thread scheduling can still change the last digits of
the metrics between runs.
